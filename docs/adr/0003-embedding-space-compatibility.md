# ADR 0003: Embedding Space Identity and Index Compatibility

## Status
Accepted

## Context
When vector embeddings are generated by different models (e.g. text-embedding-004 vs minilm vs multilingual-e5), different revisions, or different dimensional projections, their vector spaces are completely incompatible. Comparing or storing vectors from different spaces in the same index yields meaningless cosine similarity scores and degrades retrieval silently.

## Decision
1. **Explicit Vector Space Metadata**: Every vector, embedding provider, and vector index must declare its embedding space identity:
   - `provider_id`: Unique identifier for the provider.
   - `model_id`: Canonical model name and immutable revision/version.
   - `dimensions`: Exact dimension count (e.g. 384, 768).
   - `distance_metric`: Cosine, DotProduct, or Euclidean (L2).
   - `normalized`: Boolean indicating whether vectors are unit normalized.
   - `language_coverage`: List of ISO language codes explicitly supported.
2. **Pre-Query & Pre-Index Validation**: Before computing similarity or indexing a chunk, the system must validate that the query vector space matches the index vector space. Incompatible dimensions or model spaces must trigger an explicit `IncompatibleEmbeddingSpaceError` rather than silently proceeding.
3. **Migration & Re-Embedding**: When an embedding model is changed or updated, the system must initiate a versioned index migration rather than appending to an existing vector index.

## Consequences
- Positive: Prevents corrupt searches and degraded accuracy caused by mixed vector spaces.
- Positive: Safe runtime errors when configurations mismatch.
- Trade-off: Ingested documents must track their embedding model identity and trigger re-embedding when the active model changes.
